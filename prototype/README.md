# PinNote — прототип для передачи в разработку

Последняя согласованная версия интерфейса от 23 ноября 2026 года.

## Что передать другой модели

Передайте папку `prototype` вместе с исходниками проекта PinNote. Начать работу можно с задания в конце этого файла.

| Файл | Назначение |
| --- | --- |
| [index.html](index.html) | Готовый интерактивный прототип для браузера |
| [source.html](source.html) | Читаемый исходник интерфейса с CSS, JavaScript и демоданными |
| [SPEC.md](SPEC.md) | Описание поведения, карта текущего кода, отличия серверной модели и критерии приёмки |

Откройте `index.html` в современном браузере. Интерфейс и значки встроены в файл, основные сценарии доступны без подключения к сети. Сборка и установка пакетов для просмотра не требуются.

Для просмотра мобильного варианта уменьшите ширину окна. В прототипе панель переходит в режим наложения при ширине области до 740 px.

## Что посмотреть

1. В списке задач переключите «Активные», «Закрытые» и «Все».
2. Откройте «Задача-12». Меню ⋯ находится напротив «К задачам», а общая кнопка «Принять» — справа от прогресса.
3. Выберите правку и нажмите «Принять правку» под диалогом. Прогресс увеличится, соответствующий пин исчезнет с сайта.
4. Нажмите «Ответить». Поле ввода откроется и получит фокус. Отправьте реплику или сохраните черновик через «Отмена».
5. Примите остальные правки задачи. Общая кнопка «Принять» станет доступна. После её нажатия задача завершится, а текущей станет следующая открытая.
6. Завершите оставшиеся открытые задачи. Включите значок комментария, выберите элемент сайта и отправьте первый комментарий. Новая задача появится после отправки и автоматически станет текущей.

В демонстрации диалог относится к выбранной правке. Номер текущей задачи в верхнем баре определяет, чьи активные комментарии показываются на сайте и куда добавляется новый комментарий.

## Как устроен комплект

`source.html` содержит исходный фрагмент последнего прототипа. `index.html` содержит готовую автономную оболочку для просмотра с встроенной библиотекой Lucide 1.8.0. Текст лицензии библиотеки включён в HTML.

Прототип использует локальные демоданные и воспроизводит состояния интерфейса. Подключение реального API, работа агента, захват произвольного DOM-элемента и координаты пинов реализуются в основном приложении. Тёмная страница слева служит примером подключённого сайта.

Дата и время существующих демонстрационных задач фиксированы. У новой задачи время берётся в момент создания. Демонстрация форматирует время для Europe/Moscow.

В экспортированной версии исключены вспомогательные обработчики подсказок, вкладок и каруселей из среды просмотра. Все продуктовые действия, значки и курсор комментария работают локально. Для правок самого дизайна ориентируйтесь на `source.html`.

## Задание для модели-разработчика

Скопируйте этот текст в новый чат вместе с доступом к репозиторию.

```text
Реализуй согласованный интерфейс PinNote по папке prototype.

Прочитай prototype/README.md и prototype/SPEC.md. Посмотри prototype/index.html
в браузере и изучи prototype/source.html.

Перенеси UX в действующий PinNote, используя текущие модули src/client.js,
src/client.css, src/shared.mjs, src/server.mjs и src/store.mjs.
В рабочем приложении область сайта должна содержать исходный DOM подключённого проекта.

Реализуй верхний бар с резервированием места, два экрана панели, фильтры задач,
принятие правки и задачи, раскрываемый ответ, выбор текущей задачи и отображение
только её активных комментариев. Новая задача создаётся вместе с первым
успешно сохранённым комментарием.

Учти раздел SPEC.md о текущей серверной модели. Текущая задача интерфейса
может находиться на проверке, тогда как существующий activeTaskId обслуживает
задачу со статусом active. Согласуй добавление комментариев и проверку полного
принятия на клиенте и сервере.

Используй существующие механизмы диалога, статусов, SSE, скриншотов,
вложений, запуска агента, CLI и хранения данных. Учти уже существующие
незакоммиченные изменения при внесении правок.

Проверь сценарии приёмки из SPEC.md, запусти npm test и проверь UI
на desktop и мобильной ширине. В результате перечисли изменённое поведение,
выполненные проверки и оставшиеся ограничения.
```
