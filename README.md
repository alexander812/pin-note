# PinNote

> Pin feedback to the page. Hand it to the agent.

PinNote — локальный review-режим для сайтов, которые генерирует AI. Вы открываете страницу, кликаете по элементам и оставляете комментарии. Инструмент складывает их в `.review/comments.json` в корне проекта вместе с DOM-контекстом, а агент в репозитории читает файл и вносит правки.

Основная идея: **не скриншот с координатами, а структурированный якорь**. У каждого комментария есть селектор, XPath, текст, HTML, вычисленные стили, размеры и подсказки по исходникам. Скриншот с пометками — дополнительный слой, а не замена якоря.

## Установка

```bash
npm install -g pin-note
pin-note ~/projects/my-site
```

Без глобальной установки:

```bash
npx pin-note ~/projects/my-site
```

## Быстрый старт из репозитория

```bash
cd ~/projects/pin-note
npm start -- ~/projects/my-site
```

Откроется `http://127.0.0.1:4174`. Сверху появится бар PinNote: название, кнопка комментирования, номер текущей задачи и переключатель панели. Бар занимает собственную строку: контент и fixed-слои сайта сдвигаются вниз на его высоту. Открытая панель задач на desktop забирает правую часть ширины; fixed-слои сайта пересчитываются в оставшуюся область. На мобильной ширине панель накладывается на сайт.

Нажмите иконку комментария — она зальётся, курсор станет перекрестием, а элементы страницы начнут подсвечиваться при наведении. Клик по элементу открывает поповер нового комментария. Панель задач открывается кнопкой «Открыть» справа в баре.

Если в проекте уже запущен dev-сервер, PinNote найдёт его сам по папке проекта. Собирать сайт в этом случае не нужно. Адрес можно указать и явно:

```bash
cd ~/projects/pin-note
npm start -- ~/projects/my-site --target http://localhost:5173
```

`~/projects/my-site` здесь — корень проекта: оттуда берутся подсказки по исходникам и туда пишутся `.review/comments.json`. Открывать нужно адрес PinNote (`http://127.0.0.1:4174`), а не dev-сервера. Без `--target` PinNote попробует найти запущенный dev-сервер сам.

Не запускай `pin-note . --target ...` из папки самого PinNote: тогда `.review` всех проектов будет общим. Если ты уже в PinNote, передай путь к проекту явно.

Если браузер не нужен:

```bash
node bin/pin-note.mjs ~/projects/my-site --no-open
```

Демо-страница:

```bash
npm run demo
```

Подробная инструкция для любого проекта — со сборками Vite/Next/Astro, автоопределением dev-сервера, `--target`, `--spa`, отдельным `--data-dir` и циклом работы с агентом: [USAGE.md](USAGE.md).

## Где лежат данные

`.review` создаётся в корне того проекта, который передан PinNote первым аргументом, а не в папке самого PinNote:

```bash
npm start -- ~/projects/my-site
# review-данные: ~/projects/my-site/.review
```

Внутри:

- `comments.json` — задачи, комментарии, статусы, диалог и якоря;
- `screenshots/` — скриншоты с пометками;
- `attachments/` — картинки и другие файлы, прикреплённые к комментариям;
- `feedback.md` — читаемое представление текущей задачи;
- `AGENT.md` — памятка для агента.

Расположение можно изменить через `--data-dir`; фактический путь показан внизу списка задач. Папка PinNote для данных не используется, если только вы явно не запустили review на ней самой.

## Как исправить комментарии

Отдельной команды «исправить» нет: PinNote складывает задачу в `.review`, а правки выполняет агент, запущенный в корне проекта.

### Один раз: связать PinNote с агентом

Чтобы не помнить путь к памятке, добавьте в `AGENTS.md` в корне целевого проекта правило:

```text
Если пользователь просит поправить комментарии PinNote, прочитай .review/AGENT.md и следуй инструкциям оттуда.
```

Для OpenCode это можно сделать один раз глобально в `~/.config/opencode/AGENTS.md` — тогда правило будет работать во всех проектах.

### Дальше каждый раз

1. Оставьте комментарии на странице PinNote (`http://127.0.0.1:4174`).
2. Откройте терминал в корне проекта — там же, где появилась папка `.review` — и запустите свой coding-агент. Например, OpenCode:

   ```bash
   opencode
   ```

   Подойдёт любой агент, который умеет работать с файлами и терминалом: Claude Code, Codex и т. п.
3. Отправьте короткий запрос:

   ```text
   Поправь комментарии PinNote.
   ```

4. Агент прочитает памятку `.review/AGENT.md`, посмотрит `pin-note tasks current --json`, найдёт исходники, внесёт правки, переведёт комментарии в статус «На проверке» через `pin-note comments resolve` и отправит задачу на проверку.
5. Вернитесь на страницу: задача будет в статусе «На проверке», а её правки — с отметкой «К проверке». Примите каждую правку кнопкой **«Принять правку»** или ответьте агенту. Когда прогресс дойдёт до «N из N», нажмите **«Принять»** — задача закроется, а все её правки получат статус «Решён».

Команды `pin-note` нужно выполнять из корня проекта, иначе CLI не найдёт `.review`. Если каталог данных задан через `--data-dir`, передавайте его и в этих командах. Если `pin-note` не установлен в `PATH`, используйте `node <путь-к-pin-note>/bin/pin-note.mjs` с теми же аргументами.

## Как это работает

1. `npm start -- <папка>` поднимает Node-сервер и раздаёт статический сайт из указанной папки. Если в этой папке запущен dev-сервер, PinNote находит его сам и проксирует, учитывая `base` из конфига Astro/Vite/Next/Nuxt/Svelte; `--target <url>` задаёт адрес явно, `--base <path>` — базовый путь вручную, `--no-detect` отключает поиск.
2. Перед `</body>` сервер на лету вставляет `client.js` — и в статический HTML, и в HTML, полученный от dev-сервера. Сам `index.html` не меняется.
3. Клик по элементу открывает поповер. Можно прикрепить скриншот элемента с пометками и загрузить свои файлы; комментарий уходит на `POST /__review/comments` и попадает в текущую незакрытую задачу.
4. Сервер пишет данные в `.review` **в корне целевого проекта** (первый аргумент, например `~/projects/my-site/.review`): `comments.json`, скриншоты в `screenshots/`, файлы в `attachments/` и `feedback.md` для текущей задачи.
5. Агент, запущенный в корне этого проекта, читает задачу через `pin-note tasks current`, правит исходники и собирает сайт.
6. В статическом режиме сервер замечает изменение HTML/CSS/JS и перезагружает вкладку по SSE. В режиме прокси перезагрузкой и HMR занимается dev-сервер; WebSocket-соединения тоже проксируются. Если в этот момент в панели есть неотправленный текст, перезагрузка откладывается до отправки/отмены; черновики ответов и правок сохраняются в `localStorage` на случай HMR-перезагрузки.
7. Агент обновляет `status` и `resolution` комментариев (статус «На проверке»), затем выполняет `pin-note tasks submit`. Задача переходит в «На проверке»; человек принимает каждую правку в панели и завершает задачу кнопкой «Принять». Сервер повторно проверяет, что все правки приняты. При закрытии комментарии становятся «Решён».

## Что умеет

- Hover-подсветка элемента и клик для комментария.
- Адаптивный выбор: на ширине ≤740 px клик по элементу только подсвечивает его, а поповер комментария открывается кнопкой с карандашом в баре. Рядом — кнопка со стрелкой вверх: она поднимает выделение на родительский узел (можно нажимать несколько раз). На desktop поповер открывается сразу, а родитель выбирается Alt/Option+кликом.
- `Alt/Option+клик` — подниматься по дереву элементов; повторный клик выбирает родителя выше.
- Тёмная digital/AI-тема: моноширинная типографика, фиолетовый неон и встроенные JetBrains Mono / Martian Mono. Стили панели живут в Shadow DOM; на страницу добавляются только отступ под бар, ширина панели, пересчёт fixed-слоёв и курсор.
- Верхний бар с номером текущей задачи и переключателем панели. Сайт сдвигается под бар; на desktop панель резервирует правую часть ширины, на мобильной накладывается поверх сайта. `position: fixed`-слои сайта (шапки, полноэкранные сцены, HUD) пересчитываются в новую область. Модальные окна сайта (`<dialog>` с `showModal()`, popover-слои, fullscreen) не перекрывают PinNote: бар и панель остаются доступны поверх оверлея, а комментарии можно ставить прямо по содержимому модалки.
- Русский и английский интерфейс: язык автоматически выбирается по языку браузера (русский для `ru`, иначе английский), переключатель RU/EN находится в верхнем баре. Ручной выбор запоминается в `localStorage`.
- Два экрана панели: список задач с фильтрами «Активные», «Закрытые», «Все» и подробности выбранной задачи.
- Пины на странице показывают активные правки текущей незакрытой задачи. Номера пинов совпадают со строками списка правок.
- Статусы комментария: `open` (открыт), `review` (на проверке), `approved` (проверен), `rejected` (отклонён), `resolved` (решён), `wontfix` (не правим), `orphaned` (не найден).
- Правки: номер, короткое название, статус и прогресс «Принято правок». «Принять правку» переводит комментарий в `approved` и убирает его пин с сайта.
- Полное принятие задачи: кнопка «Принять» активна, когда приняты все правки. Сервер повторно проверяет это условие и отклоняет неполное принятие.
- Комментарий как диалог: первое сообщение заказчика, ответ агента из `resolution`, причина закрытия без правки, затем ответы заказчика. Ответ в диалоге сохраняется в `comments.json` и сразу передаётся агенту, если он настроен; отдельной кнопки для этого не нужно.
- Любое сообщение заказчика — первое или ответ в диалоге — можно отредактировать: у него есть кнопка с карандашом в конце. Правка сохраняется в `comments.json`, помечается как «изменено» и не запускает агента сама по себе; править можно только сообщения заказчика, не ответы агента и не системные записи.
- Загрузка файлов в поповере комментария: картинки, PDF, текстовые и любые другие файлы до 32 МБ (до 10 штук). Они лежат в `attachments/` и доступны агенту из `comments.json`.
- Задачи: номер, дата и время, короткое описание, статусы «В работе», «На проверке», «Закрыта». Новый комментарий попадает в текущую незакрытую задачу; первый комментарий создаёт задачу.
- Под списком задач — кнопка «Добавить задачу»: создаёт пустую задачу, делает её текущей и сразу открывает её. Предыдущие задачи остаются «В работе»; описание новой задачи заполняется текстом первой правки.
- Текущая задача хранится отдельно от просматриваемой: можно открыть закрытую задачу и смотреть историю, пока пины и новые комментарии относятся к открытой.
- Внизу панели задачи, под разделителем, одна контекстная кнопка: «Отправить всё агенту», если есть правки в работе и агент свободен; «Принять всё», если все правки на проверке (принимает их и завершает задачу); «Принять задачу», если все правки уже приняты. «Отправить всё агенту» отправляет не только открытую задачу, а все задачи с правками в работе: закрытые, полностью принятые и задачи без правок в работе (только «На проверке») пропускаются. Задачи выполняются агентом по очереди. Пока агент работает, кнопка становится «Остановить агента»: нажатие прерывает выполнение и очищает очередь, но остальная панель остаётся доступной. Внутри выбранной правки строка состояния показывает, где она сейчас: ждёт агента, у агента, на проверке или принята. Закрытие или удаление задачи во время работы агента тоже останавливает его.
- Правка, над которой агент работает сейчас, блокируется только она сама: у неё скрывается «Ответить» и карандаш редактирования, а на месте «Ответить» появляется «Остановить агента». Остальные правки задачи остаются доступными.
- Меню `⋮` в шапке задачи: отправить агенту, остановить или сбросить сессию, скопировать задание, закрыть или удалить задачу. Закрытие и удаление подтверждаются в панели.
- AI-агент по команде из меню задачи: DSH, Codex CLI или произвольная команда. Каждая задача получает отдельную сессию агента; отклонённый комментарий автоматически уходит на доработку в сессию этой задачи.
- Пока агент работает, панель показывает одной строкой текущее действие: какую команду он выполняет, какой файл правит, что ищет. Строка берётся из JSON-событий Codex/DSH и видна в шапке диалога выбранной правки. Ответ на правку сразу возвращает её агенту на рассмотрение, а внутри правки отображается её текущее состояние.
- Мастер `pin-note wizard`: спрашивает папку и агента, проверяет готовность, сохраняет `.review/agent.json` и запускает сервер. Запускается и просто по `pin-note` без аргументов.
- Проверка готовности агента без запуска сервера: `pin-note agent check`.
- Сохранение комментариев в `<проект>/.review/` и генерация `feedback.md`.
- Копирование Markdown для вставки в чат агенту.
- Автообновление комментариев и страницы через SSE. Если сайт пересобрался, пока вы пишете ответ или правите комментарий, PinNote не перезагружает вкладку под вами: текст сохраняется в `localStorage`, в баре появляется кнопка «Обновить сайт», а автоперезагрузка выполняется после отправки или отмены ввода.
- Fallback: если API перестал отвечать после загрузки страницы, клиент продолжает работать с `localStorage`; задание можно скопировать через меню задачи.
- Подсказки по исходникам: сервер ищет текст, id и классы по `src/*`, `app/*`, `pages/*` и соседним файлам.
- Режим `--target`: reverse proxy к Vite/Next/Astro dev-серверу, инъекция клиента в проксируемый HTML и проброс WebSocket/HMR.
- Автоопределение запущенного dev-сервера по папке проекта на macOS и Linux.
- Разделение проектов: свой `.review` по умолчанию, `projectId` в конфиге и отдельное пространство комментариев в localStorage.
- Скриншот выбранного элемента: захват вкладки, обрезка по элементу, рисование линий семью цветами, сохранение PNG и привязка к комментарию.

## Что пока не входит

- Скриншоты всей страницы и произвольной области: сейчас захватывается выбранный элемент (видимая часть).
- Отдельный режим для canvas/WebGL: сейчас клик по canvas сохраняет селектор canvas и относительную точку клика, но не область и не кадр.
- Комментарии внутри iframe.
- Обход жёсткого CSP, который запрещает same-origin-скрипты.
- Сайты с активным service worker: он может перехватывать `/__review/*`; для review-сессии его лучше отключить.
- Автоопределение dev-сервера за пределами macOS/Linux (Windows, Docker/WSL): там адрес нужно передавать через `--target`.
- Пауза анимаций.
- Расширение Chrome и работа с чужими сайтами.
- Авторизация и шаринг. Сервер слушает `127.0.0.1` и не предназначен для публикации.

Это следующие шаги, если базовый цикл окажется удобным.

## Формат комментария

```json
{
  "id": "c_m3k2_9f1a2b",
  "taskId": "t_m3k2_1a2b",
  "status": "open",
  "comment": "Заголовок слишком близко к графику, добавь 24px",
  "url": "http://127.0.0.1:4174/#2015",
  "anchor": {
    "selector": "#chapter-2015 h2",
    "xpath": "/html[1]/body[1]/main[1]/section[3]/h2[1]",
    "tag": "h2",
    "text": "2015",
    "html": "<h2 class=\"chapter__title\">2015</h2>",
    "ancestors": ["section#chapter-2015.chapter", "main#stage"],
    "attributes": { "class": "chapter__title" },
    "rect": { "x": 120, "y": 340, "width": 210, "height": 48 },
    "point": { "x": 0.5, "y": 0.5 },
    "viewport": { "width": 1440, "height": 900, "dpr": 2 },
    "scroll": { "x": 0, "y": 1210 },
    "styles": { "font-size": "64px", "margin-bottom": "8px" }
  },
  "sourceHints": [
    { "file": "src/app.js", "line": 123, "match": "text" }
  ],
  "screenshot": {
    "file": "screenshots/s_m3k2_9f1a2b.png",
    "width": 640,
    "height": 480
  },
  "attachments": [
    {
      "file": "attachments/a_m3k2_7c1d.txt",
      "name": "Заметка клиента.txt",
      "type": "text/plain",
      "size": 128
    }
  ],
  "thread": [
    {
      "id": "m_m3k2_4e8a",
      "role": "agent",
      "kind": "resolution",
      "text": "Поправил отступ",
      "at": "2026-11-10T14:05:00.000Z"
    },
    {
      "id": "m_m3k2_9b2c",
      "role": "user",
      "kind": "reply",
      "text": "Нужно 24px, а не 16px",
      "at": "2026-11-10T14:10:00.000Z"
    }
  ],
  "resolution": "",
  "createdAt": "2026-11-10T14:00:00.000Z",
  "updatedAt": "2026-11-10T14:10:00.000Z"
}
```

`sourceHints` — эвристика, а не гарантия. Агент должен проверить совпадение по селектору, тексту и HTML. Если у комментария есть `screenshot.file` или `attachments[]`, файлы лежат относительно `.review`; на скриншоте могут быть цветные пометки.

`comment` — первое сообщение заказчика. `thread[]` — продолжение диалога: `role: "user"` — заказчик, `role: "agent"` — ответ исполнителя, `role: "system"` — итог без правки. Ответ заказчика через панель возвращает комментарий в работу (`open` или `rejected`) и снова попадает агенту. Если сообщение заказчика отредактировали, у него появляется `editedAt`, а у первого сообщения — `editedAt` самого комментария; `at` остаётся временем отправки.

`feedback.md` — человекочитаемая версия текущей (или последней) задачи. Он генерируется сервером; редактировать его вручную не нужно. Источник правды — `comments.json`.

Добавь `.review/` в `.gitignore` целевого проекта, если не хочешь коммитить отзывы вместе с кодом.

## Протокол для агента

В `.review/AGENT.md` в корне целевого проекта сервер создаёт памятку. Кратко:

```text
1. Посмотри текущую задачу: pin-note tasks current --json.
   Если активной нет — возьми последнюю незакрытую: pin-note tasks list --json.
2. Возьми открытые комментарии: pin-note comments list --task current --status open --json.
3. Отклонённые комментарии могут остаться в задаче на проверке:
   pin-note comments list --status rejected --json; детали — pin-note comments show <id>.
4. У отклонённых прочитай rejection.reason — что нужно доделать.
5. Прочитай весь диалог в thread[]: последний ответ заказчика может уточнять
   или отклонять предыдущую правку.
6. Найди исходник по anchor.selector, anchor.text, anchor.html и sourceHints.
   Если есть screenshot.file или attachments[], открой файлы относительно .review.
7. Внеси минимальную правку.
8. Отметь результат: pin-note comments resolve <id> --resolution "..." (статус «На проверке»).
   Текст resolution попадёт в диалог как ответ агента.
9. Когда все комментарии разобраны — pin-note tasks submit.
   Не закрывай задачу: это делает человек.
```

Достаточно короткого запроса (если в `AGENTS.md` настроено правило из раздела «Как исправить комментарии»):

```text
Поправь комментарии PinNote.
```

Сервер сам обновит `feedback.md` и пришлёт изменения в открытую вкладку. Задача
переходит в «На проверке»: новые комментарии уже попадают в следующую задачу,
а закрытие остаётся за человеком. Отклонённые комментарии возвращаются агенту
с причиной в `rejection.reason`; при закрытии задачи все её комментарии становятся
«Решён».

## AI-агент из панели

Быстрый старт — просто запусти `pin-note` без аргументов в терминале:

```bash
pin-note
# или явно:
pin-note wizard
```

Мастер спросит папку проекта и агента, проверит готовность, предложит сохранить
настройки в `.review/agent.json` и запустит review-сервер. Если для проекта уже есть
`.review/agent.json`, он покажет сохранённого агента и модель и спросит: использовать их
или выбрать другого агента/модель. После проверки готовности новый выбор можно
подтвердить или вернуться к выбору. Путь можно передать сразу:
`pin-note wizard ~/projects/my-site`. В неинтерактивном окружении мастер не запускается;
`--no-wizard` отключает его принудительно.

Проверить готовность агента отдельно, без запуска сервера:

```bash
pin-note agent check --project ~/projects/my-site
pin-note agent check --agent codex --json
```

Проверка смотрит на команду запуска, профиль DSH `headless`, ключ `DEEPSEEK_API_KEY`
или сохранённый вход, а для Codex — на `codex login status`. Для custom-агента
проверяется только наличие команды: протокол обмена заданием не стандартизован.

Если Codex или DSH не установлены, мастер предложит поставить их глобально через npm:
`npm install -g @openai/codex` или `npm install -g @deepseek-ai/dsh`. То же без вопроса
делает `pin-note agent check --agent codex --install`. Установка выполняется только после
явного `Y`; `sudo` не используется.

PinNote может сам запускать агента, который разбирает задачу. По умолчанию он ищет
`dsh` в `PATH` (а на macOS — установленный DeepSeek Harness Desktop), затем `codex`.
Во время работы агента под кнопкой показывается одна строка активности: `Выполняет: npm test`,
`Правит: src/App.tsx`, `Ищет: ...`. Для Codex это события `item.started` / `item.completed`
(`command_execution`, `file_change`, `mcp_tool_call`, `web_search`), для DSH — `tool_call`
и `status` из `--json`. Если custom-агент не печатает структурированные события, остаётся
нейтральное «работает…».
Явно выбрать провайдера:

```bash
pin-note . --agent dsh       # DeepSeek Harness, headless-профиль
pin-note . --agent codex     # Codex CLI
pin-note . --agent custom --agent-command /path/to/agent
pin-note . --no-agent        # только комментарии, без агента
```

Пункт **«Отправить агенту»** в меню `⋮` задачи передаёт текущую задачу агенту. У каждой
задачи свой `agentSessionId`: первый запуск создаёт новую сессию, повторные — продолжают
её. Для Codex CLI PinNote добавляет безвредный оверрайд `-c log_dir=...`: он обходит
известный сбой `workspace routing discovery failed` при старте CLI. Ответ в диалоге по правке сохраняется как ответ заказчика; если агент настроен,
он сразу уходит в сессию этой задачи. В меню `⋮` также есть «Остановить агента»,
«Сбросить сессию агента» и «Скопировать задание».

Настройки можно положить в `<data-dir>/agent.json` (по умолчанию `.review/agent.json`):

```json
{
  "provider": "dsh",
  "command": "dsh",
  "args": ["--profile", "headless", "--permission-mode", "workspace-write", "--json", "-"],
  "resumeArgs": [
    "--profile", "headless", "--permission-mode", "workspace-write", "--json",
    "--session-id", "{sessionId}", "-"
  ],
  "env": {},
  "autoRework": true,
  "timeoutMs": 7200000
}
```

Для Codex:

```json
{
  "provider": "codex",
  "model": "gpt-5.4",
  "args": ["exec", "--json", "--sandbox", "workspace-write", "--skip-git-repo-check", "-"],
  "resumeArgs": ["exec", "resume", "{sessionId}", "--json", "--skip-git-repo-check"]
}
```

`model` необязателен: если он не задан, Codex берёт модель из `~/.codex/config.toml`
(ключ `model`) или использует свою модель по умолчанию. Если поле задано, PinNote
добавляет `--model <name>` к аргументам Codex.

### Codex: вход и модель

Codex CLI поддерживает два способа входа:

```bash
# вход через ChatGPT (открывает браузер)
codex login

# вход по API-ключу OpenAI
printenv OPENAI_API_KEY | codex login --with-api-key

# проверить, какой вход активен
codex login status
```

Мастер при выборе Codex проверяет `codex login status`. Если вход не выполнен,
он предложит запустить `codex login` через ChatGPT или покажет команду для API-ключа.

Вход через ChatGPT использует лимиты тарифа ChatGPT; API-ключ оплачивается по
стандартным ценам OpenAI API. Данные входа Codex хранит в `~/.codex/auth.json`
или в системном credential store (настраивается `cli_auth_credentials_store`).
`CODEX_HOME` меняет каталог `~/.codex`.

Модель выбирается так:

- мастер показывает список из 10 популярных моделей и пункт «другая модель»:
  `gpt-6.1-sol`, `gpt-6-astra`, `gpt-6-sol`, `gpt-6-luna`, `gpt-5.6-sol`,
  `gpt-5.6-terra`, `gpt-5.5`, `gpt-5.4`, `gpt-5.4-mini`, `gpt-5.3-codex-spark`;
- можно выбрать пункт «из `~/.codex/config.toml`» или ввести любой свой id;
- либо укажи `"model": "..."` в `.review/agent.json`;
- либо запусти `pin-note . --agent codex --model <модель>`;
- если ничего не указано — действует `model` из `~/.codex/config.toml` или
  модель Codex по умолчанию.

Список в мастере — ориентир, а не гарантия доступа: конкретная модель должна быть
доступна твоему тарифу ChatGPT или API-ключу.

Доступность конкретной модели зависит от тарифа ChatGPT или прав API-ключа.
`pin-note agent check --agent codex` показывает активный вход и выбранную модель.

Для DSH модель задаётся не PinNote, а профилем `headless` (`agent-default-model`);
у headless нет отдельного флага `--model`.

`args` используются для новой сессии, `resumeArgs` — для продолжения; в аргументах
доступны `{sessionId}`, `{taskId}`, `{taskTag}` и `{project}`. Задание агента передаётся
в stdin. Сессия агента хранится в `comments.json` в полях `agentSessionId` и
`agentProvider`.

DSH headless не использует вход из GUI: ему нужен ключ провайдера в окружении запуска
или в `.env` проекта/`$DSH_HOME/.env`. Чтобы headless использовал сохранённый вход
DSH Desktop, добавь в `$DSH_HOME/profiles/headless/cordis.patch.yml`:

```yaml
- id: credentials
  disabled: false
- id: authorization
  disabled: false
- id: deepseek-account
  disabled: false
```

Codex использует свою авторизацию. Если агент завершился с ошибкой, она видна в панели,
а полный лог доступен через `GET /__review/tasks/:ref/agent`.

Агент получает текст комментариев как задание и может менять файлы проекта. Запускайте
его только на проектах, которым доверяете.

## CLI

```text
pin-note [directory] [options]

  directory           Папка со статическим сайтом или корень проекта
                      (по умолчанию текущая; в ней ищется dev-сервер)
  -p, --port <port>   Порт review-сервера (по умолчанию 4174)
      --host <host>   Хост (по умолчанию 127.0.0.1)
      --target <url>  Явно указать адрес dev-сервера (например http://localhost:5173)
      --base <path>   Базовый путь сайта (например /portfolio), если он не определился сам
      --no-detect     Не искать dev-сервер автоматически
      --data-dir <dir> Каталог для comments.json, feedback.md и AGENT.md (относительно текущей папки)
      --source-dir <dir> Где искать исходники для подсказок (по умолчанию <directory>)
      --spa           Отдавать index.html для неизвестных HTML-маршрутов (статический режим)
      --agent <name>  AI-агент: dsh, codex, custom или off
      --agent-command <cmd>  Команда агента
      --agent-config <file>  JSON-конфиг агента (по умолчанию <data-dir>/agent.json)
      --no-agent      Не запускать AI-агента
      --no-wizard     Не запускать мастер при вызове без аргументов
      --no-open       Не открывать браузер
      --no-watch      Не следить за файлами
  -h, --help
  -v, --version
```

Команды задач и комментариев (работают без запущенного сервера):

```text
pin-note tasks list [--json]
pin-note tasks current [--json]
pin-note tasks show T-1 [--json]
pin-note tasks submit [T-1]        # агент отправляет задачу на проверку
pin-note tasks close T-1 --confirm # закрывает человек
pin-note tasks update T-1 --description "Короткое описание"
pin-note tasks delete T-1 --confirm

pin-note comments list [--task current|all|T-1] [--status open] [--json]
pin-note comments show <id> [--json]
pin-note comments resolve <id> --resolution "..."   # статус «На проверке»
pin-note comments set-status <id> --status review|resolved|wontfix|orphaned --resolution "..."
pin-note comments reopen <id>
```

Если `pin-note` не установлен в `PATH`, используй
`node ~/projects/pin-note/bin/pin-note.mjs ...` или выполни `npm link` в папке PinNote.

Пример с отдельным каталогом данных:

```bash
node bin/pin-note.mjs ~/projects/my-site/dist --source-dir ~/projects/my-site --data-dir ~/projects/my-site/.review
```

Пример с запущенным dev-сервером (адрес ищется автоматически):

```bash
node bin/pin-note.mjs ~/projects/my-site
```

Если dev-сервер не найден или нужен конкретный адрес:

```bash
node bin/pin-note.mjs ~/projects/my-site --target http://localhost:5173
```

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/__review/config` | Имя проекта, пути к файлам, текущая задача, возможности |
| `GET` | `/__review/state` | Задачи и комментарии |
| `GET` | `/__review/tasks` | Список задач со сводкой |
| `POST` | `/__review/tasks` | Создать пустую активную задачу и сделать её текущей; необязательное поле `description` |
| `GET` | `/__review/tasks/:ref` | Задача и её комментарии |
| `PATCH` | `/__review/tasks/:ref` | Изменить `description` |
| `POST` | `/__review/tasks/:ref/submit` | Отправить задачу на проверку |
| `POST` | `/__review/tasks/:ref/accept` | Полное принятие: требует, чтобы все правки были приняты (`approved`, `resolved` или `wontfix`); закрывает задачу и переводит комментарии в `resolved` |
| `POST` | `/__review/tasks/:ref/close` | Досрочно закрыть задачу; все её комментарии становятся `resolved` |
| `GET` | `/__review/agent` | Состояние AI-агента и его задачи |
| `POST` | `/__review/agent/dispatch` | Отправить агенту все задачи с правками в работе; `taskId` задаёт первую задачу, остальные выполняются по очереди |
| `POST` | `/__review/tasks/:ref/agent` | Отправить задачу агенту (`mode`: `task` или `rework`) |
| `POST` | `/__review/tasks/:ref/agent/cancel` | Остановить агента |
| `DELETE` | `/__review/tasks/:ref/agent` | Сбросить сессию агента |
| `GET` | `/__review/tasks/:ref/agent` | Статус агента по задаче и лог |
| `DELETE` | `/__review/tasks/:ref` | Удалить задачу и её комментарии |
| `GET` | `/__review/comments` | Весь store |
| `POST` | `/__review/comments` | Создать комментарий (можно с `attachments[]` и `taskId` текущей незакрытой задачи) |
| `PATCH` | `/__review/comments/:id` | Обновить `status`, `comment`, `resolution`, `rejectionReason` |
| `POST` | `/__review/comments/:id/messages` | Добавить ответ в диалог; `dispatchAgent: true` сразу запускает агента |
| `PATCH` | `/__review/comments/:id/messages/:messageId` | Отредактировать текст сообщения заказчика; ставит `editedAt` и синхронизирует `rejection.reason` |
| `POST` | `/__review/comments/:id/reopen` | Вернуть комментарий в текущую задачу |
| `DELETE` | `/__review/comments/:id` | Удалить комментарий |
| `GET` | `/__review/export.md` | Markdown; `?status=open&task=current` для фильтра |
| `POST` | `/__review/screenshots` | Загрузить PNG/JPEG/WebP скриншот |
| `GET` | `/__review/screenshots/:name` | Отдать скриншот |
| `POST` | `/__review/attachments?name=...&type=...` | Загрузить файл (тело запроса — байты файла) |
| `GET` | `/__review/attachments/:name` | Отдать файл; `?name=...` для имени при скачивании |
| `GET` | `/__review/events` | SSE: `comments`, `reload`, `agent` |
| `GET` | `/__review/client.js` | Клиент review-режима |
| `GET` | `/__review/client.css` | Стили в Shadow DOM |

JSON-мутации принимают только `application/json`, загрузка вложений — тело файла; все мутации требуют same-origin. API не отдаёт CORS-заголовки.

## Безопасность

- По умолчанию сервер слушает только `127.0.0.1`.
- Каталог `.review` не отдаётся статикой.
- API проверяет `Origin` для мутаций и требует JSON.
- В режиме прокси трафик идёт только на локальный dev-сервер — явно указанный или найденный по папке проекта; не направляйте PinNote на недоверенные сайты.
- Скриншоты и вложения сохраняются в `.review/screenshots` и `.review/attachments` и могут содержать данные страницы; они не отдаются статикой, только через review API. Небезопасные типы файлов отдаются с `Content-Disposition: attachment`.
- Не выставляйте сервер в сеть без аутентификации: комментарии и DOM-контекст могут содержать чувствительные данные.
