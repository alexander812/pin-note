# PinNote на любом проекте

PinNote — не расширение для браузера. Он поднимает собственный сервер на `127.0.0.1:4174` и умеет работать в двух режимах:

- **статический** — раздаёт папку со сборкой;
- **прокси** — подключается к уже запущенному dev-серверу (Vite, Next, Astro и т. п.), вставляет свой клиент в проксируемый HTML и пробрасывает WebSocket/HMR. Адрес можно указать через `--target` или дать PinNote найти запущенный dev-сервер по папке проекта.

В обоих случаях цикл одинаковый:

1. Получить страницу: собрать статику или запустить dev-сервер.
2. Запустить PinNote на папку сборки или на корень проекта: запущенный dev-сервер найдётся автоматически, а `--target` задаёт адрес вручную.
3. Оставить комментарии в браузере.
4. Попросить агента разобрать `.review/comments.json`.
5. Проверить результат: в статическом режиме пересобрать проект, в режиме прокси — дождаться HMR.

Короткая версия для проекта со сборкой в `dist`:

```bash
cd ~/projects/my-site
npm run build
pin-note dist --source-dir . --data-dir ./.review
```

Короткая версия для запущенного dev-сервера:

```bash
cd ~/projects/my-site
npm run dev

# в другом терминале
pin-note .
```

Если автоопределение не сработало, укажи адрес явно: `pin-note . --target http://localhost:5173`. Если dev-сервера нет и нужна статика, добавь `--no-detect`.

Самый короткий путь — запустить `pin-note` без аргументов в терминале. Откроется мастер:
он спросит папку проекта и агента, проверит готовность и запустит сервер. Если настройки
уже сохранены, мастер предложит использовать их или выбрать другого агента/модель;
после проверки готовности выбор можно подтвердить или изменить. То же самое
делает `pin-note wizard`; путь можно передать сразу — `pin-note wizard ~/projects/my-site`.
В скриптах и CI мастер не запускается, а `--no-wizard` отключает его принудительно.

Проверить агента без запуска сервера:

```bash
pin-note agent check --project ~/projects/my-site
pin-note agent check --agent codex --json
```

Проверка смотрит на команду запуска, профиль DSH `headless`, ключ модели/сохранённый
вход, а для Codex — на `codex login status`.

Если Codex или DSH не установлены, мастер предложит установить их глобально через npm
(`npm install -g @openai/codex` / `npm install -g @deepseek-ai/dsh`) — только после
ответа `Y`. Без вопроса то же делает `pin-note agent check --agent codex --install`.

Здесь и ниже команда `pin-note` предполагает alias из следующего раздела. Без него используй `node "$HOME/projects/pin-note/bin/pin-note.mjs"`.

Дальше — подробности.

## 1. Подготовка (один раз)

Нужен Node.js 20+.

Чтобы не писать полный путь к PinNote каждый раз, добавь alias в `~/.zshrc` или `~/.bashrc`:

```bash
alias pin-note='node "$HOME/projects/pin-note/bin/pin-note.mjs"'
```

Альтернатива — поставить команду в `PATH`:

```bash
cd ~/projects/pin-note
npm link
```

После этого везде ниже можно использовать `pin-note` вместо длинного пути.

В `.gitignore` целевого проекта добавь:

```text
.review/
```

Так комментарии и служебные файлы review не попадут в коммит. Если хочешь хранить отзывы вместе с кодом — не добавляй.

### Связать PinNote с агентом

Чтобы агенту хватало короткого запроса «Поправь комментарии PinNote», один раз добавь в `AGENTS.md` в корне проекта:

```text
Если пользователь просит поправить комментарии PinNote, прочитай .review/AGENT.md и следуй инструкциям оттуда.
```

Для OpenCode можно добавить это правило глобально в `~/.config/opencode/AGENTS.md`; тогда оно будет работать во всех проектах.

### Что считается проектом

Проект — это каталог, который передан PinNote первым аргументом. По умолчанию данные лежат в `<этот каталог>/.review`, а в `--target`-режиме оттуда же берутся подсказки по исходникам. Поэтому:

- запускай PinNote из корня проекта или передавай путь явно;
- не запускай `pin-note . --target ...` из папки самого PinNote — иначе `.review` станет общим для всех проектов;
- не передавай один и тот же `--data-dir` разным проектам без необходимости.

Имя проекта видно в баре PinNote, а фактический путь к `comments.json` — внизу списка задач. Это быстрый способ проверить, что открыт нужный проект.

## 2. Статический режим: какую папку раздавать

Этот раздел нужен, если PinNote запускается на папку со сборкой. Если в этой папке найден запущенный dev-сервер, PinNote автоматически переключится в режим прокси; чтобы принудительно раздавать статику, добавь `--no-detect`. Для явного `--target` переходи к разделу 6.

| Проект | Сборка | Папка для PinNote |
| --- | --- | --- |
| Обычный статический сайт | не нужна | корень проекта |
| Vite (React, Vue, Svelte) | `npm run build` | `dist` |
| Create React App | `npm run build` | `build` |
| Next.js со static export | `npm run build` с `output: 'export'` | `out` |
| Astro | `npm run build` | `dist` |
| Nuxt | `npm run generate` | `.output/public` |
| SvelteKit с adapter-static | `npm run build` | `build` |

Для проекта со сборкой:

```bash
cd ~/projects/my-site
npm run build

pin-note dist \
  --source-dir . \
  --data-dir ./.review
```

Замени `dist` на папку из таблицы. Что делают опции:

- `--source-dir .` — искать подсказки по исходникам в корне проекта, а не в собранных файлах. Без этого `sourceHints` будут бесполезны.
- `--data-dir ./.review` — хранить `comments.json` и `feedback.md` в корне проекта. Тогда отзывы переживут пересборку, которая часто очищает `dist`.
- `--spa` — добавить, если у приложения клиентский роутинг (React Router, Vue Router, SvelteKit SPA). Тогда прямые ссылки на внутренние маршруты будут отдавать `index.html`.

Если сайт статический и сборки нет:

```bash
cd ~/projects/my-static-site
pin-note .
```

В этом случае `--source-dir` и `--data-dir` можно не указывать: по умолчанию PinNote ищет исходники в той же папке и складывает `.review` туда же.

Относительные пути в `--data-dir` и `--source-dir` считаются от текущей папки терминала, поэтому запускай команду из корня проекта.

После старта PinNote напечатает адрес:

```text
Review: http://127.0.0.1:4174
```

Открывай именно его, а не адрес dev-сервера. Если порт 4174 занят, PinNote без явного `-p` попробует следующие порты и покажет фактический адрес в терминале.

## 3. Как оставлять комментарии

1. Открой адрес, который напечатал PinNote. Браузер откроется сам, если запуск был из терминала.
2. В верхнем баре нажми иконку комментария (контур). Она зальётся, курсор станет перекрестием, и включится режим review. Бар занимает свою строку, контент и fixed-слои сайта сдвигаются ниже него.
3. Наведи курсор на элемент: он подсветится рамкой и подписью с тегом.
4. Кликни по элементу. Откроется поповер с якорем: селектор, тег и текст элемента.
5. Напиши комментарий и нажми **⌘↵** (macOS) или **Ctrl+Enter** (Windows/Linux). **Esc** закрывает поповер без сохранения. После сохранения режим review выключится, а подсветка исчезнет.
6. Если попал не в тот элемент, кликни с зажатым **Alt** (на Mac — **Option**): будет выбран родительский элемент. Повторный Alt/Option+клик поднимает ещё выше по дереву. Поповер при этом остаётся открытым, а уже введённый текст сохраняется.

Дальше:

- В баре виден счётчик правок, требующих внимания, и номер текущей задачи. Панель открывается кнопкой **«Открыть»** справа в баре.
- На экране «Задачи» фильтры **«Активные»**, **«Закрытые»** и **«Все»**. Карточка показывает дату, статус, номер задачи, описание и число правок. Нажатие открывает задачу.
- Под списком задач есть кнопка **«Добавить задачу»** со значком `+`. Она создаёт пустую задачу, делает её текущей и открывает её подробности. Предыдущие задачи остаются «В работе», а описание новой заполнится текстом первой правки.
- В задаче сверху прогресс «Принято правок», список правок с номерами и статусами, ниже — диалог по выбранной правке.
- **«Принять правку»** переводит правку в `approved`, обновляет прогресс и убирает её пин с сайта. Когда приняты все правки, активируется общая кнопка **«Принять»**; сервер повторно проверяет это условие.
- Кнопка **«Ответить»** раскрывает поле, и в нём подписано, что ответ уйдёт агенту. Отправка сохраняет ответ в диалоге и сразу возвращает правку агенту на рассмотрение; отдельного подтверждения не требуется. Внутри правки строка состояния показывает, где она сейчас. **⌘↵** / **Ctrl+Enter** отправляет, **Esc** сворачивает поле и сохраняет черновик правки.
- Клик по пину или по строке правки прокручивает страницу к элементу и подсвечивает его. Если сайт отрисовывает далёкие секции только при прокрутке (виртуализация, scroll-driven анимации), PinNote сначала возвращается к сохранённой позиции прокрутки, а затем подсвечивает элемент.
- Меню `⋮` в шапке задачи: «Отправить агенту», «Остановить агента», «Сбросить сессию агента», «Скопировать задание», «Закрыть задачу», «Удалить задачу». Закрытие и удаление подтверждаются в панели.
- Просмотр закрытой задачи не меняет текущую открытую задачу: пины и новые комментарии продолжают относиться к ней.
- Режим review не мешает переходить по страницам сайта: у каждого комментария сохраняется URL.

### Скриншот с пометками

В поповере комментария есть кнопка **«Скриншот элемента»**:

1. Нажми её и выбери **вкладку с сайтом** (не окно и не весь экран).
2. PinNote скроет свою панель, сделает кадр и обрежет его по выбранному элементу.
3. На открывшемся холсте рисуй линии мышью или пальцем; цвет выбирается из семи вариантов.
4. **«Отменить»** убирает последнюю линию, **«Очистить»** — все линии.
5. **«Прикрепить»** добавляет скриншот к комментарию. Перед сохранением его можно убрать крестиком.

Скриншот сохраняется в `.review/screenshots`, а в `comments.json` появляется поле `screenshot.file`. Агент увидит путь и изображение с пометками. Захват работает только при открытом review-сервере и в secure context (`localhost`/`127.0.0.1`).

### Загрузка файлов

Рядом с кнопкой **«Скриншот элемента»** есть **«Загрузить файл»**:

1. Нажми её и выбери одну или несколько картинок или любых других файлов (до 10 файлов, до 32 МБ каждый).
2. Прикреплённые файлы видны в поповере; крестик убирает файл до сохранения комментария.
3. После сохранения файлы лежат в `.review/attachments`, а в `comments.json` появляется `attachments[]` с именем, типом и размером.
4. В карточке комментария картинки открываются превью, остальные файлы — ссылкой на скачивание.

Загрузка работает только через review-сервер. Вложения не отдаются статикой: сервер отдаёт их через API, а потенциально активные типы — как скачиваемый файл.

Ограничение: сейчас захватывается выбранный элемент и его видимая часть. Скриншот всей страницы или произвольной области не поддерживается.

Комментарии сохраняются сразу на диск:

```text
.review/comments.json   источник правды: задачи, комментарии, диалог и вложения
.review/feedback.md     человекочитаемая версия текущей задачи, генерируется сервером
.review/AGENT.md        краткая памятка для агента
.review/screenshots/    PNG-скриншоты с пометками
.review/attachments/    файлы, прикреплённые заказчиком
```

Имя проекта показано в баре, путь к `comments.json` — внизу списка задач.

`feedback.md` вручную не редактируй: при следующем изменении сервер перезапишет его из `comments.json`.

Пока идёт review, терминал с PinNote не закрывай: сервер пишет комментарии и отдаёт страницу.

## 4. Как подключить агента

Агент должен работать в репозитории проекта. Запустите его в терминале из корня проекта — например, командой `opencode` — и отправьте короткий запрос:

```text
Поправь комментарии PinNote.
```

Правило из `AGENTS.md` подскажет агенту прочитать `.review/AGENT.md`, где описаны команды и порядок действий.

Комментарии группируются в задачи: новый комментарий попадает в текущую незакрытую задачу, а первый комментарий создаёт задачу. После `tasks submit` задача переходит в «На проверке»; новые комментарии в неё по-прежнему можно добавлять, пока она не закрыта. Агент переводит разобранные комментарии в «На проверке»; вы принимаете каждую правку кнопкой «Принять правку», а затем завершаете задачу кнопкой «Принять». Ответ в диалоге возвращает правку агенту с причиной.

Если `--data-dir` указывает в другое место, добавь его к командам `pin-note`.
Если `pin-note` не установлен в `PATH`, используй
`node <путь-к-pin-note>/bin/pin-note.mjs` с теми же аргументами.
В режиме прокси (`--target` или автоопределение) после правок ничего пересобирать
не нужно: dev-сервер применит изменения через HMR.

### Задачи в браузере

Панель начинается с экрана **«Задачи»**. Фильтры «Активные», «Закрытые» и «Все»
относятся к списку задач. Карточка показывает дату и время, статус, номер задачи,
описание и число правок. Нажатие открывает подробности. Под списком закреплена
кнопка **«Добавить задачу»**: она создаёт пустую задачу, делает её текущей и сразу
открывает подробности. Задач «В работе» может быть несколько; текущая — та, куда
попадёт следующий комментарий.

На desktop сайт и панель делят ширину окна, а fixed-слои сайта (шапка, сцена, HUD) пересчитываются в оставшуюся область; на мобильной панель накладывается на сайт.

В подробностях сверху — «К задачам», меню `⋮`, номер задачи, дата, статус и прогресс
«Принято правок». Общая кнопка **«Принять»** активна, когда приняты все правки;
нажатие закрывает задачу и переводит её комментарии в `resolved`. Меню `⋮` содержит
«Отправить агенту», «Остановить агента», «Сбросить сессию агента», «Скопировать задание»,
«Закрыть задачу» и «Удалить задачу». Закрытие и удаление подтверждаются внутри панели.

Ниже — ограниченный по высоте список правок с отдельной прокруткой и диалог по выбранной
правке. Под диалогом закреплены **«Принять правку»** и **«Ответить»**. В самом низу панели, под разделителем, находится одна контекстная кнопка: **«Отправить всё агенту»** для правок в работе (если агент свободен), **«Остановить агента»**, пока он выполняет задачу, **«Принять всё»** когда все правки на проверке — она принимает все правки и завершает задачу, и **«Принять задачу»**, когда все правки уже приняты. **«Отправить всё агенту»** отправляет агенту все задачи с правками в работе, а не только открытую: закрытые, полностью принятые и задачи без правок в работе пропускаются, остальные выполняются по очереди. Кнопка **«Остановить агента»** прерывает текущую задачу и очищает очередь. Пока агент работает, остальные кнопки панели остаются доступными: можно переключать задачи и правки, а закрытие или удаление задачи прерывает выполнение. Ответ сохраняется
в `comments.json` и передаётся агенту, если он настроен. Просмотр закрытой задачи
не меняет текущую открытую задачу: её номер остаётся в баре, а пины на сайте
продолжают показывать активные правки текущей задачи.

Что происходит дальше:

1. Агент читает якоря и правит исходники, а не собранные файлы.
2. В статическом режиме агент пересобирает проект; в режиме прокси изменения подхватывает dev-сервер.
3. PinNote перезагружает вкладку при изменении статической сборки, а в режиме прокси это делает HMR dev-сервера.
4. Сервер следит за `comments.json` и обновляет статусы в панели.

Если вкладка не перезагрузилась сама, обнови её вручную. Если статусы не появились, нажми иконку обновления в шапке списка задач.

`feedback.md` генерируется из `comments.json`; если он почему-то отстаёт, источником правды всё равно остаётся JSON.

### Агент по кнопке

PinNote может запускать агента прямо из панели. При старте он ищет `dsh` в `PATH`
(на macOS — ещё и установленный DeepSeek Harness Desktop), затем `codex`:

```bash
pin-note . --agent dsh       # DeepSeek Harness headless
pin-note . --agent codex     # Codex CLI
pin-note . --no-agent        # только комментарии
```

Пункт **«Отправить агенту»** в меню `⋮` задачи передаёт текущую задачу агенту и создаёт
для неё отдельную сессию. Повторная отправка продолжает ту же сессию. Ответ в диалоге
по правке сохраняется как ответ заказчика и сразу передаётся агенту; отдельного
подтверждения отправки не требуется. Если агент не настроен, ответ просто сохраняется
в `comments.json`, а задание можно скопировать через меню.

Статус агента виден рядом с задачей: «Агент работает», «Агент завершил» или
«Агент: ошибка» с текстом ошибки. Пока агент работает, в шапке диалога выбранной правки
отклонённого комментария показывается одна строка: что он делает сейчас — например,
`Выполняет: npm test` или `Правит: src/App.tsx`. Информация берётся из JSON-событий
Codex/DSH. Нижняя кнопка в это время становится **«Остановить агента»** — она
прерывает выполнение, а остальная панель остаётся доступной. Закрытие или удаление задачи
во время работы агента тоже останавливает его. В меню `⋮` можно остановить агента,
сбросить сессию или скопировать задание вручную.

Провайдер и аргументы команд задаются в `<data-dir>/agent.json` (обычно
`.review/agent.json`). Полный пример и формат — в [README.md](README.md#ai-агент-по-кнопке).
Задание передаётся агенту в stdin; сессия хранится в задаче (`agentSessionId`).
DSH headless берёт ключ провайдера из окружения или `.env`, а не из входа в GUI.
Агент получает текст комментариев и может менять файлы проекта — запускайте его
только на доверенных проектах.

#### Codex: вход и модель

Codex CLI подключается к аккаунту одним из двух способов:

```bash
codex login                                  # вход через ChatGPT, браузер
printenv OPENAI_API_KEY | codex login --with-api-key  # API-ключ OpenAI
codex login status                           # проверить активный вход
```

Мастер проверяет `codex login status` и, если вход не выполнен, предложит запустить
`codex login` через ChatGPT или покажет команду для API-ключа.

Вход через ChatGPT расходует лимиты тарифа, API-ключ оплачивается по ценам OpenAI API.
Кэш входа лежит в `~/.codex/auth.json` или в системном credential store.

Модель:

- мастер показывает 10 популярных моделей (`gpt-6.1-sol`, `gpt-6-astra`,
  `gpt-6-sol`, `gpt-6-luna`, `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.5`,
  `gpt-5.4`, `gpt-5.4-mini`, `gpt-5.3-codex-spark`), вариант «из config.toml»
  и пункт «другая модель» для ручного id;
- в `.review/agent.json` можно задать `"model": "..."`;
- или `pin-note . --agent codex --model <модель>`;
- иначе Codex берёт `model` из `~/.codex/config.toml` или использует модель по умолчанию.

Список — ориентир; доступность модели зависит от тарифа ChatGPT или API-ключа.

`pin-note agent check --agent codex` покажет и вход, и выбранную модель.
У DSH модель задаётся профилем `headless`, а не PinNote.

## 5. Полный цикл на примере

```bash
# 1. Собрать сайт
cd ~/projects/my-site
npm run build

# 2. Запустить review
pin-note dist --source-dir . --data-dir ./.review

# 3. Оставить комментарии в http://127.0.0.1:4174

# 4. В другом окне попросить агента разобрать текущую задачу PinNote,
#    пересобрать проект и выполнить pin-note tasks submit

# 5. Принять правки в браузере и закрыть задачу кнопкой «Принять»
#    через ⋮ → «Закрыть задачу». Все её комментарии станут «Решён».
# 6. Остановить PinNote: Ctrl+C
```

Для dev-сервера:

```bash
# 1. Запустить dev-сервер (в своём терминале)
cd ~/projects/my-site
npm run dev

# 2. В другом терминале запустить PinNote поверх него
#    (адрес dev-сервера PinNote найдёт сам; если нет — добавь --target)
pin-note .

# 3. Оставить комментарии в http://127.0.0.1:4174

# 4. Попросить агента разобрать текущую задачу PinNote и выполнить
#    pin-note tasks submit. Пересобирать не нужно: dev-сервер применит правки через HMR.
```

После правок проверьте комментарии в панели и закройте задачу. Новые комментарии создадут следующую задачу. Старые остаются в JSON со статусом `resolved`.

## 6. Режим прокси: работа с dev-сервером

Если проект уже запущен через Vite/Next/Astro, собирать его не нужно:

```bash
cd ~/projects/my-site
npm run dev

# в другом терминале, тоже из корня проекта
pin-note .
```

PinNote сам находит запущенный dev-сервер: смотрит локальные порты, сопоставляет рабочий каталог процесса с папкой проекта и проверяет, что сервер отдаёт HTML. Базовый путь (`base` в Astro/Vite, `basePath` в Next, `baseURL` в Nuxt) определяется по конфигу проекта; корень PinNote перенаправляет на этот путь. Если сервер один, адрес подставляется автоматически. Если найдено несколько — PinNote покажет список и попросит `--target`.

- Первый аргумент — **корень проекта**, а не папка сборки: оттуда берутся `sourceHints` и туда пишется `.review`.
- Не запускай `pin-note .` из папки самого PinNote: тогда комментарии всех проектов попадут в `~/projects/pin-note/.review`. Если ты уже находишься в PinNote, укажи путь явно: `pin-note ~/projects/my-site`.
- У каждого проекта должен быть свой `.review`. Не передавай один и тот же `--data-dir` разным проектам.
- `--target http://localhost:5173` нужен, если автоопределение не сработало, сервер запущен в Docker/WSL или найдено несколько кандидатов. Порт должен совпадать с тем, что напечатал dev-сервер.
- `--base /portfolio` задаёт базовый путь вручную, если PinNote не смог прочитать его из конфига. В `--target` указывай origin без этого пути.
- `--no-detect` принудительно отключает поиск dev-сервера и включает статический режим.
- Автоопределение работает на macOS и Linux. На Windows, в Docker/WSL и для dev-серверов с нестандартным рабочим каталогом используй `--target`.
- Открывай Review URL (`http://127.0.0.1:4174`), а не адрес dev-сервера. PinNote проксирует запросы и вставляет клиент в HTML на лету.
- WebSocket и HMR пробрасываются, поэтому правки агента применяются без пересборки. Если HMR не работает, проверь, что dev-сервер слушает тот же хост, на который указывает `--target`.
- API, авторизация, SSR и server components работают как в обычном dev-режиме: PinNote не подменяет приложение, а проксирует его.
- Service worker может перехватывать `/__review/*`; на время review-сессии его лучше отключить.
- Если dev-сервер отдаёт жёсткий CSP, клиент может не загрузиться. Для review ослабь CSP или используй статическую сборку.
- Поддерживается локальный `http://` или `https://` target (для https сертификат должен быть доверенным). Это не прокси для чужих сайтов из интернета.

Если dev-сервер недоступен, PinNote вернёт 502. Запусти его и обнови страницу.

## 7. Если что-то не работает

| Симптом | Причина и решение |
| --- | --- |
| Нет иконки комментария | Открыт адрес dev-сервера или `file://`, а не адрес PinNote. Проверь, что в DOM есть `<script data-pin-note>`; посмотри ошибки в консоли. |
| Кнопки нет из-за CSP | Жёсткий CSP может блокировать встроенный клиент. Для review-сессии ослабь CSP или используй сборку без него. |
| В статическом режиме внутренний маршрут отдаёт 404 | Добавь `--spa`. В режиме прокси маршруты обрабатывает dev-сервер. |
| Страница пустая или без стилей | Не та папка сборки или неверный `--target`. Проверь, что в папке есть `index.html`, а dev-сервер отвечает по указанному адресу. В режиме прокси базовый путь (`base: '/sub/'`) определяется автоматически или задаётся через `--base /sub`; статическую сборку с `base: '/sub/'` для review пересобери с `base: '/'`. |
| PinNote отвечает 502 | До dev-сервера из `--target` не достучаться. Проверь, что он запущен и слушает тот же хост и порт. |
| Порт отличается от 4174 | Порт занят, PinNote взял следующий. Открой адрес из терминала или задай `-p 4180` явно. |
| Комментарии пропали после сборки | `--data-dir` указывал внутрь `dist`, а сборка очистила папку. Используй `--data-dir ./.review` в корне проекта. |
| В списке комментарии другого проекта | Запусти PinNote из корня нужного проекта или передай его первым аргументом. Проверь путь к `comments.json` внизу списка задач: у разных проектов не должно быть одного `--data-dir`. |
| Агент завершился с кодом 2 | Codex 0.171+ больше не принимает `--full-auto`. PinNote использует `--sandbox workspace-write`; если в `.review/agent.json` остались свои `args` с `--full-auto`, удали их и перезапусти PinNote. |
| `AGENT // workspace routing discovery failed` | Сбой bootstrap Codex CLI. PinNote добавляет обходной `-c log_dir=...` (openai/codex#52928); перезапусти PinNote. Если ошибка осталась — обнови Codex CLI и выполни `codex login`, затем проверь `codex exec --skip-git-repo-check "Reply OK"` в терминале. |
| Агент не видит комментарии | Запусти `pin-note comments list --task current --json` из корня проекта. Для отклонённых — `pin-note comments list --status rejected --json`. Если данные лежат в другом месте, передай `--data-dir`. |
| Агент обновил статусы, а браузер их не показал | Нажми иконку обновления в шапке списка задач или перезагрузи страницу. |
| Не закрывается задача | В задаче остались правки не в статусе `approved` (например, `open`, `review`, `rejected` или `orphaned`). Примите их кнопкой «Принять правку»; полное принятие сервер проверяет повторно. |
| Новые комментарии попали в старую задачу | Задача ещё `active`. Попроси агента выполнить `pin-note tasks submit` или закрой задачу вручную; после этого новые комментарии создают следующую. |
| Вкладка не перезагружается после правок | В статическом режиме пересобери проект. В режиме прокси перезагрузку и HMR делает dev-сервер: проверь его консоль и WebSocket. Если запускал с `--no-watch`, обновляй вкладку вручную. |
| HMR/WebSocket не подключается | Проверь, что `--target` указывает на тот же хост и порт, который слушает dev-сервер. Некоторые dev-серверы требуют явно разрешить WebSocket на другом origin. |
| Dev-сервер запущен, но PinNote его не нашёл | Автоопределение работает на macOS/Linux и требует, чтобы рабочий каталог процесса был внутри папки проекта. Для Windows, Docker/WSL или нестандартного запуска укажи адрес через `--target`. |
| Комментарий сохранился только в браузере | Сервер стал недоступен, клиент перешёл в localStorage. Верни сервер, скопируй задание через меню `⋮` задачи и создай комментарии заново. |
| Нужен комментарий к iframe или области canvas | Ограничение версии: iframe не поддерживается, у canvas сохраняется только точка клика, без области и кадра. |
| Кнопка скриншота не работает | Нужен `localhost`/`127.0.0.1` (secure context), запущенный review-сервер и браузер с `getDisplayMedia`. При запросе выбери вкладку с сайтом, а не окно или экран. |
| Скриншот не появился у агента | Проверь поле `screenshot.file` в `comments.json` и файл в `.review/screenshots`; `feedback.md` должен содержать ссылку `![Скриншот](screenshots/...)`. |

## 8. Опции запуска

| Опция | Назначение |
| --- | --- |
| `-p, --port <port>` | Порт review-сервера, по умолчанию `4174`. |
| `--host <host>` | Хост, по умолчанию `127.0.0.1`. |
| `--target <url>` | Явно указать адрес dev-сервера, например `http://localhost:5173`; без него PinNote ищет сервер сам. |
| `--base <path>` | Базовый путь сайта, например `/portfolio`; нужен, если PinNote не определил его по конфигу. |
| `--no-detect` | Не искать dev-сервер автоматически, работать как статический сервер. |
| `--data-dir <dir>` | Где хранить `comments.json`, `feedback.md`, `AGENT.md`. По умолчанию `<directory>/.review`; у каждого проекта должен быть свой каталог. |
| `--source-dir <dir>` | Где искать исходники для `sourceHints`. По умолчанию `<directory>`. |
| `--spa` | Отдавать `index.html` для неизвестных HTML-маршрутов (статический режим). |
| `--agent <name>` | AI-агент: `dsh`, `codex`, `custom` или `off`; без опции — автоопределение. |
| `--agent-command <cmd>` | Переопределить команду агента. |
| `--agent-config <file>` | JSON-конфиг агента; по умолчанию `<data-dir>/agent.json`. |
| `--no-agent` | Не запускать AI-агента. |
| `--no-wizard` | Не запускать мастер при вызове без аргументов. |
| `--no-open` | Не открывать браузер автоматически. |
| `--no-watch` | Не следить за файлами, `comments.json` и не перезагружать вкладку. |
| `-h, --help` | Показать справку. |
| `-v, --version` | Показать версию. |

## 9. Ограничения

PinNote делает скриншоты только выбранного элемента, не работает с iframe, не выделяет области canvas/WebGL и не обходит CSP. Чтобы бар не перекрывал контент, страница сдвигается вниз на высоту бара, панель на desktop резервирует правую ширину, а `position: fixed`-слои сайта (шапки, полноэкранные сцены, HUD) пересчитываются в новую область. Прокрутка документа при этом остаётся прежней. Сайты с нестандартными fixed-слоями, `top: auto`-позиционированием или собственной логикой прокрутки могут требовать дополнительной настройки. Прокси работает только с локальным dev-сервером — указанным явно или найденным по папке проекта; инструмент не предназначен для чужих сайтов в интернете. Сервер слушает только `127.0.0.1` и не имеет авторизации — не выставляй его в сеть.

Полный список возможностей и ограничений — в [README.md](README.md).
